# PR 124 continuation — seller child refunds and manual reversals

Draft only. These are local, isolated tests, not evidence that production is safe or ready to merge. No migration has been applied to the official Supabase project.

## Changes

- `0090_atomic_manual_wallet_reversal.sql` and `reverseTransactionAction`: an active admin may compensate a qualifying manual adjustment with one linked opposite-direction `ADJUSTMENT`, under account and original-row locks. The original is not flagged and remains in the balance calculation. Retries require identical actor/reason and consistent history; historical reversals are not rewritten. Order debits, payments, order reversals, funding changes and other events are deliberately refused; their own entitlement/settlement workflows must be used. The admin table exposes the operation only for manual adjustment rows. This does not eliminate other direct table writers/grants or reconcile legacy reversal flags.
- `0091_seller_child_cancellation_refund.sql`: the existing seller RPC now wraps its tenant-checked transition, stock restoration, parent aggregation, child-share Coins refund and final-parent coupon release in one transaction. It locks the parent before the original child transition, rejects mismatched/ambiguous refund history and already allocated seller settlement, and leaves seller accounting untouched. The pre-wrapper transition is private. An internal private balance calculation is shared by the existing authorized outstanding RPC and the ledger mirror trigger; this enables a seller-caused refund without granting sellers wallet-read access. Changes in the child cancellation transaction roll back on refund/stock failure. This is not the parent cancellation workflow.
- `0092_refund_replay_and_child_share_guard.sql`: validates all linked refund history on event replay and requires a child debit to equal its immutable Coins share. Unclear historical rows fail closed.
- Migration 0088's unwired parent cancellation still rejects all split parents. Migration 0089 correctly directs split stock back to the original owner in the covered scenarios; 0091 uses this when a final seller child moves the parent to cancelled. Migrations 0088–0092 need independent integrated review, actual Supabase service testing and all-writer hardening before deployment.
- Two previously failing seller offer tests now provide explicit positive compliance RPC results and assert the derived product and seller identity passed to both gates. No real compliance decision is simulated as a live result. Test-only lint fixes use typed doubles/imports and rename variables without changing assertions; middleware's response holder removes a lint error without changing its cookie forwarding lifecycle.

## Release blockers

- Retailer web, admin/staff and mobile parent cancellation still changes status separately from the refund; 0088 atomic RPC is unwired and rejects valid split parents. Admin child cancellation and delivery return still span multiple calls; direct DB paths can bypass app handling. A complete shared locking/authorization/stock/coupon/refund design and comprehensive application and real-platform concurrency tests remain necessary. Order debit reversal is intentionally blocked in the generic manual action, not yet replaced by a complete eligible-order workflow.
- Shortfall refunds, other manual/direct financial writers, seller settlement, retained history and all readers (including Android/mobile and truncated retailer/salesman summaries) require a full authoritative audit. Previously miscounted stock or legacy flags are not silently repaired.
- The reset inventory and design are incomplete. No DB/Auth or Storage-object backup was created, no isolated restore rehearsed and no reset performed. No Super Admin bootstrap/recovery implementation or real Auth recovery rehearsal was completed. Do not infer recoverability from existing metadata.
- Full test/lint/security gates and Android prerequisites remain unresolved. Vercel preview is not a production verification. Keep PR draft; no merge, production deployment, financial writes, reset or migrations.
