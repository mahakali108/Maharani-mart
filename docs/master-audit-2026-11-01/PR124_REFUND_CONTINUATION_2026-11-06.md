# PR #124 — refund implementation continuation (2026-11-06)

**Draft only. Do not merge, deploy, or run migration 0088 against production.** This is partial implementation, not completion of the owner's request. No production data, credentials, billing, or configuration were changed.

## What changed

- `0088_refund_ledger_integrity.sql` replaces parent/child refund RPCs for **new** events with linked credits while leaving the debit unflagged; this fixes the repository's original full-refund regression under the new migration. It adds an event-keyed partial API, rejects key reuse with mismatched amount/actor/reason, checks cumulative linked credit against the debit, locks the order, credit account and debit, and rejects inactive or unauthorized callers. The legacy child API has one fixed event key and cannot represent multiple independent partial events; the new event-keyed child API can. Existing rows are neither updated nor reinterpreted. A flagged historical debit, an unlinked order reversal, or delivery shortfall history fails closed for new refunds and needs reconciliation. These changes do **not** make all monetary ledger writes append-only.
- Draft `cancel_order_coins_atomic` performs status, existing order stock trigger effects, refund, and coupon release in one database call, with authorization and active-user checks. It refuses split orders. **No existing web, mobile, admin or seller cancellation path calls this draft function.** Those paths remain separate transactions and are a release blocker. It has not been tested with actual split-seller stock, coupon redemptions or the full checkout function. Seller transitions and return/shortfall flows remain outside the atomic design.
- The order movement reader now uses verified linked credits to show net spend for new refunds; it retains the previous display behavior for flagged historical debits rather than silently changing history. The existing cancellation verifier accepts unflagged debit plus complete linked credits. The unsafe direct-write refund fallback was removed; missing RPC now fails closed. Delivery return and admin sub-order transitions surface refund/stock failures, but their earlier status changes can already have committed. Admin sub-order transitions verify the parent and the coin share before changing status.
- Reset inventory now reports foreign keys inbound from schemas outside `public`, `auth` and `storage`. It remains **read-only and incomplete**, not a reset mechanism. No bootstrap or restore mechanism is implemented.
- The lockfile refresh resolves compatible dependency updates without overrides: nanoid 3.3.20, browserslist 4.29.5, source-map-js 1.2.2 and baseline-browser-mapping 2.11.35, plus compatible transitive dependencies. The direct package specifications are unchanged.
